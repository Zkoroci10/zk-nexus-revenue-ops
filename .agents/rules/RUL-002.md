# ZK Nexus Module Standard v1.0

**Purpose:** Defines the official 10-module root layout, folder depth limits, staging protocols, and domain boundary contracts for ZK Nexus.

---

## 1. Top-Level Module Architecture

ZK Nexus is structured into 10 top-level modules. Every folder and file in the workspace MUST reside inside one of these 10 root modules:

```
ZK Nexus/
├── 00_Command Center/     ← Navigation, master indices, health reports, AI entry point
├── 01_Business/           ← Live business unit operations & governance
├── 02_Projects/           ← Active work packages & AI staging zone
├── 03_Knowledge/          ← Reusable knowledge base, SOPs, research backlog
├── 04_Workforce/          ← Human/AI worker profiles, prompts, rules, constitution
├── 05_Systems/            ← Live code, automation scripts, UI apps, APIs
├── 06_Resources/          ← Brand assets, media files, design graphics
├── 07_Templates/          ← Reusable templates and blueprints
├── 08_Logs/               ← Immutable append-only audit records
└── 99_Archive/            ← Inactive, legacy, and historical records
```

## 2. Module Specifications & Domain Boundaries

### 2.1 `00_Command Center`
- **Domain:** Workspace navigation, health monitoring, master registries, global operating entries.
- **Key Files:** `AI-START-HERE.md`, `Workspace-Index.md`, `ID-Registry.md`, `Module-Health-Report.md`, `Daily-Control-Loop.md`.
- **Governance:** Managed primarily by Human Founder and AI-002 (ZK-Operator).

### 2.2 `01_Business`
- **Domain:** Operational business units (BUs) and live revenue-generating entities.
- **Sub-directories:**
  - `ZK-Revenue-Ops/` (VA SDR services for Real Estate Negotiators)
  - `DAE-Ecosystem/` (Future AI product venture)
  - `Business-Registry.md`
- **Governance:** Operational content must be staged in `02_Projects` before promotion. Direct edits prohibited on `Active` status docs.

### 2.3 `02_Projects`
- **Domain:** Active work packages, staging ground for all AI output, project execution tracking.
- **Sub-directories:**
  - `Active/` — Active client and revenue projects (e.g., `PRJ-004 Sales Engine`).
  - `Internal/` — Workspace cleanup, internal builds, staging drafts.
  - `Active-Projects-List.md`
- **Staging Role:** Universal staging area for AI workers. All draft files, proposals, SOPs, code modifications MUST be created here first.

### 2.4 `03_Knowledge`
- **Domain:** Centralized repository of reusable domain knowledge, SOPs, frameworks, and research.
- **Sub-directories:**
  - `Sales/`, `Finance/`, `Legal/`, `AI/`, `Research-Backlog.md`, `Knowledge-Index.md`.
- **Governance:** Maintained by AI-003 (ZK-Knowledge). Requires Founder approval for promotion to `Active`.

### 2.5 `04_Workforce`
- **Domain:** Human leadership, AI worker profiles, governance rules, prompt library, onboarding protocols.
- **Sub-directories:**
  - `Rules/` (Workspace rules RUL-001..004)
  - `Role-Definitions.md` (`IDX-011`)
  - `AI-Worker-Registry.md` (`IDX-010`)
  - `AI-Onboarding-Protocol.md` (`RUL-003`)
- **Governance:** Maintained by Human Founder and AI-001 (ZK-Architect).

### 2.6 `05_Systems`
- **Domain:** Technical assets, source code, automation scripts, web apps, database schemas, integration configurations.
- **Sub-directories:**
  - `Scripts/` (PowerShell, Node.js, Python scripts e.g., `workspace-validator.ps1`, `test-syntax.js`)
  - `Apps/` (Web UI applications, Jarvis Command Center, ZK RevOps WebApp `SYS-001`)
  - `Integrations/` (API endpoints, n8n workflows)
  - `Systems-Inventory.md` (`IDX-012`)
- **Governance:** Maintained by AI-005 (ZK-Developer).

### 2.7 `06_Resources`
- **Domain:** Static media, logos, graphic templates, presentation decks, brand guidelines.
- **Key Files:** `Asset-Catalog.md` (`IDX-014`).
- **Governance:** Maintained by AI-004 (ZK-Creator).

### 2.8 `07_Templates`
- **Domain:** Reusable blueprint templates for proposals, cold outreach emails, prompts, SOPs.
- **Key Files:** `Template-Index.md` (`IDX-015`), `TMP-001_Proposal_SDR-Pilot.md`, `TMP-002_Email_SDR-Outreach.md`, `TMP-003_Prompt_CEO-Operating-Prompt.md`.
- **Governance:** Maintained by AI-004 (ZK-Creator) and AI-003 (ZK-Knowledge).

### 2.9 `08_Logs`
- **Domain:** Immutable, append-only operational audit trail and execution logs.
- **Key Files:** `Log-Index.md` (`IDX-004`), `System-Audit.log`, daily activity logs.
- **Governance:** Strict append-only policy. No file deletion or modification permitted under any circumstances.

### 2.10 `99_Archive`
- **Domain:** Retired business units, legacy documents, completed projects, deprecated SOPs.
- **Key Files:** `Archive-Index.md` (`IDX-005`), `ZK-Nexus-Legacy/`.
- **Governance:** Read-only storage for historical reference.

## 3. Directory Depth Limits

To maintain workspace clarity, prevent deeply nested paths, and preserve filesystem efficiency, ZK Nexus enforces a strict folder depth limit:

```
[Module Root] / [Level 1 Subfolder] / [Level 2 Subfolder] / [File.md]
     │                    │                    │
     ▼                    ▼                    ▼
01_Business / ZK-Revenue-Ops / 00_Foundation / 001_Vision.md   <-- ALLOWED (2 Levels)
01_Business / ZK-Revenue-Ops / 00_Foundation / Sub / 001.md    <-- PROHIBITED (3 Levels)
```

### Depth Rules:
- **Maximum Depth:** Exactly **2 folder levels** below any top-level module root.
- **Flat Organization:** Keep files organized cleanly within Level 1 or Level 2 subdirectories.
- **Validation:** Automated workspace integrity scripts (`SYS-001` / `workspace-validator.ps1`) will flag any directory path exceeding the 2-level limit as a compliance violation.

## 4. Staging & Promotion Protocol

### 4.1 Staging Rule
- **Mandatory Staging:** ALL new operational documents, SOPs, proposals, system scripts, and templates produced by AI workers MUST be created inside `02_Projects/Active/[Project-Name]/` or `02_Projects/Internal/` first.
- **No Direct Root Writes:** AI workers MUST NOT write directly to live modules (`01`, `03`, `04`, `05`, `06`, `07`) without explicit staging and Founder review.

### 4.2 Promotion Protocol
```
1. AI Worker creates draft in 02_Projects/ (Status: Draft)
2. AI Worker completes work & updates metadata (Status: Review)
3. Human Founder reviews content during Daily Control Loop
4. Upon approval, Founder (or authorized AI) moves file to target module (Status: Active)
5. Index files (Workspace-Index, ID-Registry, Module Index) are updated
```
