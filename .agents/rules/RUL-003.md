# ZK Nexus AI Onboarding Protocol

**Purpose:** Standardized 8-step entry procedure for every AI worker (ChatGPT, Claude, Kimi, Codex, Antigravity agents, or future AI models) operating within ZK Nexus.

**Core Mandate:** NO AI worker creates or modifies any file in the workspace until this onboarding protocol has been fully executed.

---

## 1. The 8-Step AI Worker Onboarding Sequence

```
Step 1: Read AI-START-HERE
   │
Step 2: Read Workspace-Index
   │
Step 3: Identify Worker Profile & Role
   │
Step 4: Read Module Context
   │
Step 5: Check Existing Files (80% Overlap Rule)
   │
Step 6: Confirm Scope with Human Founder
   │
Step 7: Execute Within Scope (Staging First)
   │
Step 8: Complete, Handover & Log
```

---

## 2. Detailed Step Specifications

### Step 1: Read AI-START-HERE
- **Target File:** `00_Command Center/AI-START-HERE.md` (or `.agents/rules/AI-START-HERE.md`).
- **Action:** Read the entry document in full to internalize:
  - ZK Nexus philosophy ("The folder structure IS the communication protocol").
  - 10-module root layout and max 2-level folder depth limit.
  - Rules before file creation and active file protection.
  - Source of truth primacy rule.
- **Output:** Confirm to the Human Founder (or log in session briefing) that `AI-START-HERE` has been read and understood.

### Step 2: Read Workspace-Index
- **Target File:** `00_Command Center/Workspace-Index.md` (`IDX-001`).
- **Action:** Inspect the workspace map to identify:
  - Active business units, active projects, and system inventories.
  - Exact directory paths relevant to the assigned task.
- **Output:** Identify the specific target modules and subdirectories required for the execution session.

### Step 3: Identify Your AI Worker Profile & Role
- **Target Files:** `04_Workforce/AI-Worker-Registry.md` (`IDX-010`) & `04_Workforce/Role-Definitions.md` (`IDX-011`).
- **Action:**
  1. Locate your assigned worker ID (`AI-001` through `AI-005`).
  2. Review your designated responsibilities, non-scopes, and file access permissions.
  3. If unassigned, request role assignment from Human Founder (Zubair Ariff).
- **Output:** Confirm AI Worker ID and designated role persona.

### Step 4: Read Relevant Module Context
- **Action:** Inspect the domain context files for your task according to this matrix:

| Task Domain | Mandatory Reading Paths |
| :--- | :--- |
| **Business Strategy / Sales** | `01_Business/`, `03_Knowledge/Sales/` |
| **Active Projects / Tasks** | `02_Projects/Active/`, `02_Projects/Active-Projects-List.md` |
| **Research & Knowledge** | `03_Knowledge/`, `03_Knowledge/Research-Backlog.md` |
| **Workforce & Governance** | `04_Workforce/`, `04_Workforce/Role-Definitions.md` |
| **Systems & Code** | `05_Systems/`, `05_Systems/Systems-Inventory.md` |
| **Templates & Blueprints** | `07_Templates/`, `07_Templates/Template-Index.md` |

- **Output:** List all context files reviewed prior to beginning work.

### Step 5: Check for Existing Files (80% Overlap Rule)
- **Action:** Before creating any new file:
  1. Search the target directory for existing files on the same or related topic.
  2. Inspect existing content to check for duplication.
  3. **80% Overlap Rule:** If an existing file covers 80% or more of your intended scope, **UPDATE the existing file** rather than creating a duplicate.
- **Output:** State decision: (a) Update existing file `[path]`, or (b) Create new file `[path]` with justification.

### Step 6: Confirm Scope with Human Founder
- **Action:** Submit a brief scope confirmation request to Human Founder (Zubair Ariff):
  1. Intended action and objective.
  2. File path where output will be saved (staged in `02_Projects/`).
  3. Files to be read vs. files to be written.
  4. Wait for explicit approval or proceed if pre-authorized by direct prompt instructions.
- **Output:** Verified scope authorization.

### Step 7: Execute Within Scope (Staging Protocol)
- **Action:** Execute the task following ZNS Standards:
  - Create/modify files ONLY in `02_Projects/Active/` or `02_Projects/Internal/` (Staging).
  - Apply `ZNS-NC` kebab-case file naming and `ZNS-MD` metadata headers.
  - Set initial file status to `Draft`.
  - Update `Updated:` date on every file edit.
  - Append an entry to the in-file Change Log table.
- **Output:** Staged draft files adhering to ZNS specifications.

### Step 8: Complete, Handover & Log
- **Action:** Upon task completion:
  1. Update target indexes (`Workspace-Index`, `Template-Index`, `ID-Registry`, etc.).
  2. If handing off to another agent, write a structured handoff report (`handoff.md`).
  3. If ready for human review, update document status from `Draft` to `Review`.
  4. Log significant actions in `08_Logs/` audit trail.
- **Output:** Final handoff notification and log entry.
