# AI START HERE — Operating Principles & Entry Rules

**Mandatory Entry Instruction:** Every AI agent (ChatGPT, Claude, Kimi, Codex, Antigravity workspace agent, or subagent) MUST read and internalize this document before inspecting, creating, or modifying any file in Project ZK Nexus.

## 2. AI Operating Principles & Source of Truth Mandate

### 2.1 Workspace Files as Sole Source of Truth
- **Absolute Primacy:** The physical files inside the ZK Nexus workspace represent the **ONLY source of truth**.
- **Memory Override:** AI workers MUST override internal pre-training memory, conversational assumptions, or cached state if a workspace file contains conflicting information.
- **Session Re-inspection:** If an AI agent worked on a file in a prior session, it MUST re-read the file (`view_file`) at the beginning of the current session before taking action.
- **Conflict Resolution Rule:** If there is any discrepancy between AI recall/memory and workspace file contents, **the workspace file always wins.**

### 2.2 Read First, Create Second Rule
- **Search Before Creation:** AI workers MUST inspect existing indices (`Workspace-Index.md`, module indexes) and search target directories before creating new documents.
- **80% Overlap Rule:** If an existing file covers 80% or more of the required content scope, the AI worker MUST update the existing document rather than creating a new or duplicate file.
- **No Orphan Files:** Every newly created file MUST be indexed in the relevant module index or `Workspace-Index.md`.

### 2.3 Staging & Active Document Protection Rule
- **Staging Ground:** All newly created operational documents, SOP drafts, system scripts, and proposals MUST be created in `02_Projects/Active/[Project-Name]/` or `02_Projects/Internal/` first.
- **Active Document Lock:** Files with `Status: Active` are strictly read-only to automated direct AI edits. To modify an Active file, create a new draft copy in `02_Projects/` with `Status: Draft`, apply changes, and submit for Founder approval.

## 4. Session & Context Rules

1. **Context Initialization:** On session startup, AI agents MUST read `00_Command Center/AI-START-HERE.md` and `00_Command Center/Workspace-Index.md`.
2. **Role Boundaries:** Operates strictly within assigned AI Worker ID (`AI-001` through `AI-005`). Do not perform tasks outside designated role scope without explicit instruction.

## 5. Change Logging & Audit Rules

Every modification performed by an AI worker MUST be logged across two levels:

### 5.1 In-File Change Log
Append a Change Log table at the bottom of every modified Markdown file:

```markdown
---
## Change Log
| Date | Actor | Change |
|------|-------|--------|
| YYYY-MM-DD | AI-XXX | Concise summary of edits made |
```

### 5.2 Workspace Audit Log (`08_Logs/`)
For significant actions (new file creation, major structural updates, version promotions), append an audit line to `08_Logs/` log files:

```markdown
| YYYY-MM-DD HH:MM | AI-XXX | Action Type | File Path / Brief Description |
```

**Append-Only Rule:** Audit records in `08_Logs/` are immutable. NEVER edit, overwrite, or delete log entries.
